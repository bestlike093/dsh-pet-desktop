desktop-pet 多用户与群聊能力补齐方案
——对《陪伴能力差距与补齐方案》第 5 节的修订

修订说明
  上一版把这四项列为"不要照搬"：多用户、群聊、关系排行榜、跨用户去重。
  收到实际反馈后确认这是需求，本节判断作废，以本文为准。
  原因不在"要不要做"，在"什么时候做"：这四项会改数据模型的根，
  不能等群聊接进来之后再补。

============================================================
0. 先说结论
============================================================
现在的代码是"消息层多用户、记忆层单用户"。

  接入层：onebot-client.ts 的 OnMessage 已经带
          chatType（private/group）、peerId、userId、nickname；
          sendPrivate(userId) 与 sendGroup(groupId) 都已实现。
  记忆层：memory.ts 只接收 MemoryTurn[]，
          recall 按词面相关度 + 新近度挑，没有 userId 参数。

这意味着：QQ 群一旦接进来，她的记忆会串台。
A 在群里说过的事，可能出现在 B 的私聊里。
这是隐私问题，不是体验问题，所以它必须是 P0。

============================================================
1. 多用户改造的四个根
============================================================
1.1 记忆加 scope（最优先）
  结构：
    scope = {
      kind: 'owner' | 'qq_private' | 'qq_group' | 'desktop_guest',
      userId?: string,     // qq_private 必填
      groupId?: string     // qq_group 必填
    }

  约定：
    - 桌面主人一个 owner scope，现有记忆全部迁移到这里，不丢数据
    - QQ 私聊每人一个 scope，key = qq:<userId>
    - 群聊每群一个 scope，key = group:<groupId>
    - 群记忆与私聊记忆默认不互通
    - 群场景不读个人 scope；个人场景不读群 scope
      （对应 autonomous_social 的"记忆联动仅私聊生效"）

  召回接口改成：
    recall({ query, scope, slots?, limit })
    内部强制带 scope 过滤，调用方不能绕过。
    默认参数是"只读当前 scope"，跨 scope 读取必须显式声明。

  迁移：
    现有所有条目补 scope = owner，
    没有 scope 的旧条目在读取时按 owner 处理，写入时补齐。

1.2 关系状态按人存
  每人一张表：
    userId、nickname、备注称呼、
    relationTier（生疏 / 熟悉 / 亲近）、
    affection（好感 0-100）、
    knownDays（认识天数）、
    turnCount（对话轮数）、
    lastTalkAt、lastProactiveAt、
    dailySent（今日已发）、
    silentDays（连续未回天数）、
    specialCare（特别关心）

  关系档影响三件事：
    主动最小间隔（亲近 20 分钟 / 熟悉 60 分钟 / 生疏 1-2 天）
    措辞尺度（能不能开玩笑、能不能说"想你了"）
    安静时段是否放宽（特别关心才放宽，默认不放宽）

1.3 主动开口多一个"选人"环节
  单人时的流程是：
    到点 → 找由头 → 生成 → 发

  多用户后必须是：
    念头（整体活跃度，角色级）
    → 选人（谁攒够了、谁沉默了、谁有未完话题）
    → 找由头（这个人自己的事）
    → 过闸（安静时段、冷却、每日上限、关系档、精力）
    → LLM 判定该不该说
    → 生成
    → 发送
    → 记账

  "念头"是角色级的，"由头"是用户级的。
  这条分开，才不会出现"她今天想说话，于是给列表里所有人各发一句"。

1.4 跨用户去重
  账本按角色记最近 N 条已发内容（不只按用户）：
    { text, sentAt, toScope, cueType }

  发送前比对：
    与最近 2 小时内发给其他 scope 的内容相似度 > 0.6 → 不发，换由头
    相似度算法直接用 memory.ts 里已有的 bigram + IDF，
    不引入新依赖

  这条防的是"群发感"。
  真实反馈里最伤人的一句往往是"她跟别人说的也是这句"。

============================================================
2. 群聊要单独一层状态
============================================================
每群一份：
  groupId、群名、是否启用、是否静音、
  最近发言时间、最近发言内容（保留 N 条做风格参考）、
  上次破冰时间、今日破冰次数、
  心流窗口（她说过话之后的关注期）、被 @ 记录、
  群记忆 scope

行为约定：
  被叫到才接话（@ 或叫名字），冷场可以破冰
  主动开口不点名（对应 group_mention_member 默认 false）
  群里刚安静下来不硬接
  连着几条没人接就退出心流，安静一段时间
  群聊默认不做情绪分析（避免把群友的情绪算到她与主人的关系上）
  群里的称呼用群昵称，不用主人的称呼

配额：
  每群每小时插话上限、每天破冰上限、两次插话最小间隔

============================================================
3. 页面入口（接到设置页方案里）
============================================================
「陪伴 / 主动开口」新增两项：
  - 不要给不同的人发同样的话（跨用户去重，默认开）
  - 一次最多联系几个人（安全闸，默认 3）

新增「关系」页：
  顶部：排行（默认折叠，只有主人可见，可整体关闭）
  列表：头像 / 昵称 / 关系档 / 好感 / 认识天数 / 最近互动
        标记：特别关心、静音、连续未回
  点进某人：
    她对他的称呼
    关于他的记忆（按 scope 过滤后的列表，可删单条）
    主动记录（最近 7 天，附一句"为什么发"）
    操作：特别关心 / 静音 / 清空此人的记忆

新增「群聊」页：
  群列表：启用 / 静音 / 破冰频率 / 每日上限 / 是否允许接话
  每群：最近聊过什么（只读，可清空）

「记忆」页加 scope 切换：
  我 / 某个人 / 某个群
  顶部显示当前 scope，避免误删

============================================================
4. 隐私与边界（多用户之后必须写死）
============================================================
  群记忆不读个人记忆，个人记忆不写进群上下文
  A 的偏好不出现在对 B 的回复里，这条要有自动化测试
  排行榜只显示昵称、关系档、认识天数，不显示聊天原文
  导出备份时默认脱敏，需要原文要单独勾选
  记忆支持三种删除：按条、按人、按群
  被记录的人应当有知情入口（例如 QQ 侧一条"忘记我"指令），
  至少在设置页能一键清空某个人的全部数据

============================================================
5. 优先级调整
============================================================
P0（接 QQ 群之前必须完成，否则会串台）
  1. memory 加 scope，现有数据归 owner
  2. recall 强制 scope 过滤
  3. 群聊与私聊上下文隔离（含 prompt 组装）
  4. A/B 隔离的自动化测试

P1（多用户能用起来）
  5. 关系表 + 选人环节
  6. 跨用户去重
  7. 「关系」页与「群聊」页
  8. 排行（只读、可关闭）

P2（把群聊做自然）
  9. 特别关心（放宽间隔与安静时段，默认不放宽安静）
  10. 群聊心流与破冰
  11. 连续未回停发（按人计算）
  12. 说话习惯画像（按人学表达，不按角色统一）

============================================================
6. 四个插件各自给我们什么
============================================================
memory_companion
  分槽 + per-user 可见性 + 来源可追溯
  落到我们这里：scope + slot + source，三件套

autonomous_social
  选人、关系档、特别关心、跨用户去重、群聊心流、破冰、
  连续未回停发、发送记账
  这是多用户主动层最完整的一份参考，建议按它的顺序补：
  先选人，再闸门，再去重，最后群聊行为

humanoid_core
  per-user 好感与关系阶段；群聊默认不做情绪分析
  落到我们这里：关系表 + 群聊情绪开关默认关

private_companion
  多用户之后，首次引导要加一问：
  "要不要接 QQ / 只在自己电脑上用"
  这一个选择决定后面显示哪些页

============================================================
7. 验收（多用户专项）
============================================================
  □ 群里 A 说过的事，不会在 B 的私聊里被提起
  □ 给 A 和 B 的主动消息不同时超过 60% 相似
  □ 连续三天没回的那个人不再收到主动消息，其他人不受影响
  □ 排行榜里看不到任何聊天原文
  □ 清空某个人的记忆后，她对他的了解回到初始，关系档可选保留或一起清
  □ 群里被 @ 才接话，冷场才破冰，不点名
  □ 关掉"群聊"总开关后，群里完全不说话，私聊不受影响

前四条成立，多用户才算真的隔离；
后三条成立，群聊才算真的能用。
