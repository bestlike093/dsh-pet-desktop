## 它解决什么

桌宠常见的两种做法都有明显代价：一种把某只模型焊死在窗口里，换形象就得改代码；另一种把所有功能塞进一个进程，一处崩全盘崩。

这个项目按两条线拆开：

- **渲染与模型解耦**：image / gif / video / live2d / sprite 共用一套 `IModel` 契约，换模型不改宿主。
- **能力与核心解耦**：模块系统提供了清单、权限和失败边界。桌面壳目前的功能仍是内建实现，还没有加载第三方模块。

依赖方向由脚本卡住，不靠自觉：

```
modules → core → vault / memory → shared
```

## 安装与启动

需要 Node.js 18 以上，包管理器是 pnpm。

```bash
pnpm install
pnpm start          # 启动
pnpm test           # 单元测试
pnpm verify         # 完整门禁
```

`pnpm verify` 会依次跑构建、类型检查，再过这些检查：

| 检查 | 拦什么 |
| --- | --- |
| `check-electron-syntax` | 主进程脚本语法 |
| `check-assets-license` | 素材授权登记 |
| `check-third-party` | 第三方声明 |
| `check-ipc-contract` | IPC 通道白名单 |
| `check-capability-literals` | 能力字符串硬编码 |
| `check-shared-purity` | shared 层纯度 |
| `check-module-boundaries` | 依赖方向 |
| `check-api-catalog` | 对外 API 目录 |
| `check-probe-residue` | 探针残留 |
| `contract-snapshot` | 契约快照 |

想只跑门禁不重新构建，用 `pnpm verify:gate`。

## 第一次打开

首次启动会引导你做三件事，每一项都可以跳过，之后在设置里改：

1. **怎么称呼你**：昵称只用于气泡文案，留空时用「你」。
2. **要不要接模型**：填自己的 API Key。不填也能用，只是没有对话能力。
3. **要不要出声**：语音默认关闭，打开后可以再选什么时候允许说话。

引导末尾还有一个「从备份恢复」入口。换过机器、或者想直接搬回旧配置时，在这一步导入 `.petbackup` 就行，不用先走完引导再去设置里找。

中途关掉引导也算没走完，下次启动会再出现。

## 形象与模型

渲染层是一张适配器注册表，五种形象走同一套接口：

| 类型 | 说明 |
| --- | --- |
| `image` | 单张静态图 |
| `gif` | 逐帧动画 |
| `video` | 视频循环 |
| `live2d` | PixiJS + `pixi-live2d-display` |
| `sprite` | 雪碧图切帧 |

模型文件不进仓库，也不进安装包。Live2D 模型由你自己从作者处下载后导入，统一放在用户数据目录的 `models/` 下，这样卸载重装、换版本都不会丢，也不受安装目录写权限限制。

启动时会先试当前模型；没导入、文件缺失或加载失败，就降级到随包立绘，并在界面上说明原因。开发期可以用 `PET_MEDIA_ROOT` 把模型目录临时指到别处。

## 动作与描边

### 动作走三层通道

导入的 Live2D 素材常常不带 motion——`motionManager.definitions` 是空的，只调 `model.motion()` 会静默失败。所以动作按能力从强到弱排了三层，每层都能判断是否真的生效：

| 通道 | 做什么 | 什么时候可用 |
| --- | --- | --- |
| `native` | 模型自带的 motion / expression | 素材本身提供了才有 |
| `param` | 写 Cubism 标准参数曲线，例如 `ParamAngleX` | 绝大多数 Cubism 模型都有 |
| `pixi` | 改 DisplayObject 的位移、缩放、旋转 | 任何媒体都吃这套，兜底不空转 |

走到哪一层会如实上报，状态栏和日志里能看到。

动作本身是一张表，每个动作由几条轨道加时长组成：

| 动作 | 别名 | 说明 |
| --- | --- | --- |
| `nod` | 点头 / 同意 / 嗯 | 上下两摆 |
| `shake` | 摇头 / 不是 / 不对 | 左右两摆 |

`aliases` 同时是 AI 的可用词汇：模型只要报出 key 或中文别名，就能被解析到对应动作。没有对应参数的动作（比如整体弹跳）会自动只走 `pixi`。

### 描边颜色自动判断

立绘贴在浅色桌面或深色壁纸上，边缘容易糊成一片。描边颜色由「轮廓外圈可见像素的平均亮度」决定：

| 条件 | 效果 |
| --- | --- |
| 平均亮度 > 150 | 亮色立绘，配深色边 `#181820` |
| 平均亮度 ≤ 150 | 深色立绘，配白边 `#ffffff` |

深色边没用纯黑，留了一点蓝紫，跟界面的暗部一致。

采样只取外圈一圈像素——描边加在轮廓外侧，画面中心的衣服颜色说明不了问题。外圈全透明时（立绘没铺满画布，很常见）退回整幅不透明像素，并标明用的是哪种取样。

采样失败时（画布空、被污染、还没渲染）不改样式，把原因回传出去，不会随便挑一个颜色假装成功。

## 语音

两个独立设置，都在「设置 → 语音」里：

| 设置 | 可选值 | 说明 |
| --- | --- | --- |
| 触发时机 | 每条 / 仅主动搭话 / 仅手动 | 决定哪些内容会被念出来 |
| 免打扰时段 | 自定义起止时间 | 时段内不发声，气泡照常显示 |

默认不主动出声，免打扰默认是 22:00 到 08:00，跨零点时起始时间大于结束时间即可。

合成路线有两条：

- **本地**：默认地址 `http://127.0.0.1:9880`，只接受回环地址。协议默认 `gpt-sovits`，本机 IndexTTS v2 与 GPT-SoVITS 都认这套参数；自建接口可改回 `generic`。参考音频要在设置里填服务端本机路径，留空时本地合成会被跳过，不会报错。
- **云端**：需要自己填完整接口地址和音色标识，按量计费，费用由你自己的账户承担，界面展示的金额带 `≈` 前缀，表示估算值。

其它几个防刷屏的参数：单条朗读最多 60 字，超出截断；两次自动开口至少隔 8 秒；播放音量只作用于本机，不影响服务端。

第一次开启语音时才会请求系统音频权限。

## 聊天与记忆

聊天默认关闭，要自己填 Key 才能开。

- 服务商目前只支持 DeepSeek，端点写死在主进程，渲染侧无法指定地址，避免把 Key 发到任意服务器。
- 默认模型 `deepseek-chat`，单次最多 800 token，温度 0.8，每次请求带 10 条历史。
- 人格提示词默认注入，可以在设置里追加一段风格说明。

记忆也是默认关闭，装完不会悄悄存东西。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 最多保留 | 500 条 | 超出按权重淘汰 |
| 摘要间隔 | 每 8 轮 | 触发一次压缩 |

聊过的内容加密后存成 `memory.bin`；没有加密仓库时直接不写，明文不落盘。聊天窗的历史单独一份 `chat.bin`——记忆是给模型的摘要，历史是给你回看的记录。

## 陪伴与主动说话

主动说话由一层情景区拼出来，不再是渲染层里一个静态数组轮播。每次要开口时，它整理这几件事：

| 输入 | 来源 |
| --- | --- |
| 时间 | 几点、星期几、是不是深夜 |
| 天气 | open-meteo 免密钥接口，按设置里的城市取，15 分钟缓存 |
| 陪伴 | 这次开机陪了多久、上次被点是什么时候 |
| 心情 | 由时间与陪伴推导出的轻量状态，只影响措辞 |
| 记忆 | 注入 `getMemoryDigest()`，只取摘要，不读原始记录 |

生成的句子最多 40 字，气泡放得下，也不会变成一段独白。任何一环失败都不抛错：天气拿不到就少写天气，模型调不通就退回本地短句。

这一项默认关闭，关着的时候不发任何外部请求。

### 情绪与陪伴任务

下面几项同样默认关闭，开了也只影响本机表现：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 情绪余波 | 关 | 半衰期默认 30 分钟，范围 5–720 |
| 表情表达 | 关 | off / experiment / control 三组对照 |
| 需求状态 | 关 | 只调整主动开口的排序 |
| 每日终盘巡视 | 关 | 默认 22:30，复盘当天表现 |
| 逐案复盘 | 关 | 默认 23:00，逐条判断前一天的问题 |
| 人格问卷 | 关 | 从人格文本归纳表达风格 |
| 需求强化 | 关 | 按需求层级调整主动开口 |

陪伴任务共用一份每日 token 预算，默认 20000，设 0 表示不限。巡视报告只写进 `reports/`，反思只写进 `notes/reflection/`，文件名只接受日期，路径不接受渲染侧传入。

## 状态栏

状态栏显示在立绘旁边，由三个设置控制：

| 设置 | 取值 | 说明 |
| --- | --- | --- |
| 显隐 | 开 / 关 | `showHud`，默认关 |
| 详细度 | `full` / `simple` / `simple2` | `hudDetail` |
| 透明度 | 0–1 | `hudAlpha`，默认 0.9 |

三档详细度：

| 档位 | 显示内容 |
| --- | --- |
| `full` | 完整读数，进来就摊开 |
| `simple` | 一行简读数，藏起头像与模型名 |
| `simple2` | 头像 + 心情 / 模型，数字点开才露 |

老配置里写的 `off` 会自动归一成 `simple`，显隐只由 `showHud` 决定，不用手动改配置。

### 指标怎么采

| 指标 | 采样方式 | 间隔 |
| --- | --- | --- |
| CPU | `node:os` 两次 tick 差值 | 3 秒 |
| 内存 | `os.totalmem` / `os.freemem` | 3 秒 |
| 网速 | PowerShell 读网卡累计字节，差值除以间隔 | 6 秒 |
| 电量 | PowerShell 读 `Win32_Battery`，台式机返回 `null` | 6 秒 |
| GPU | 型号走 `app.getGPUInfo('basic')`，利用率尝试 `nvidia-smi` | 随慢采样 |

缺数据时弧归零、数字写「—」、整格降饱和，鼠标悬停会说明是哪一项拿不到，不会用假数字填满界面。单项失败只影响这一项，不影响其它指标，也不会把异常抛到主流程。

PowerShell 脚本是常量字符串，不拼接任何用户输入，也不接受参数；单次调用超时 8 秒，失败后 30 秒再试，避免每拍都拉起一个进程。

环形读数的半径是 16 逻辑像素，用 `stroke-dasharray` 控制弧长。

## 素材包

自定义素材通过统一引用格式挂进界面：

```
pack:<包 id>:<包内文件名>
```

四个地方认这个格式：

| 位置 | 配置字段 | 说明 |
| --- | --- | --- |
| 字体 | `bubble.fontFamily` | 空串用内置字体栈 |
| 气泡底图 | `bubble.background` | 空串用纯 CSS 外观，填了按九宫格拉伸 |
| 气泡旁贴纸 | 贴纸字段 | 空串表示关闭 |
| 托盘 / 任务栏图标 | 图标字段 | 空串用内置素材 |

贴纸与状态栏头像共用同一个边长（`bubble.stickerSize`，逻辑像素）。气泡的行高倍数在 1.2–2.4 之间调。

随包素材有一份清单，打包前会跑体积审计，确认没有多余文件混进发布包。

## 模块系统

模块不是插件市场的概念，是宿主内的能力单元。每个模块有清单、权限和失败边界：

| 组件 | 作用 |
| --- | --- |
| `petalManifest` | 清单校验 |
| `moduleLoader` | 加载与卸载 |
| `moduleSandbox` | 失败隔离 |
| `permissionBroker` | 权限申请与授予 |
| `hostCapability` | 宿主能力注入 |
| `disposer` | 资源回收 |

内置三个模块，开关在配置里：

| 模块 | 默认 | 权限 |
| --- | --- | --- |
| `builtin.bubble` | 开 | `ui.render` |
| `builtin.reminder` | 开 | `memory.read` / `memory.write` |
| `builtin.balance` | 关 | `net.egress` |

`builtin.balance` 默认关，因为它要外网 + API Key，首次启动就发请求会让「装完能不能跑」的验证被网络噪音干扰。

模块崩掉不会带走整个进程；失败会被隔离，界面留一个占位卡片说明哪个模块出了问题。

### 余额监控

`builtin.balance` 默认关。打开后按 `settings.balance.intervalMinutes` 轮询，改间隔下一轮生效。

账本 `balance-ledger.json` 是 v1 结构，按本地日切保留最近 7 天，写入时裁剪；每片记 `tz`、`fetchedAt`、`balance`、`threshold`、`acknowledgedAt`、`lastAlertedAt`。旧 v0 单日账本会在第一次真正读写时一次性迁移，`fetchedAt` 与 `threshold` 留空表示未知。

迁移失败时停轮询并上报 `ledger-migrate-failed`，原文件保持可读；抓余额失败只记一次 `balance-fetch-failed`，下一轮继续。轮询调度与账本层已有测试，桌面壳接线、阈值告警与确认还在开发中。

## 远程拍板

主进程内置一个决策网关，把「需要你拍板的事」投递到手机，再把答复收回来。

QQ 走官方机器人接口，凭据只从环境变量读，不落盘、不入同步包：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `QQ_BOT_APP_ID` | 是 | 机器人 AppID |
| `QQ_BOT_SECRET` | 是 | AppSecret |
| `QQ_BOT_PUBLIC_KEY` | 是 | 验签公钥 |
| `QQ_BOT_OPENID` | 否 | 私聊目标的 openid |
| `QQ_WEBHOOK_PORT` | 否 | 默认 8787 |

webhook 只监听 `127.0.0.1`，路径固定 `/qq/webhook`，只收 POST。缺少公钥时直接不启用——没有公钥就无法验签，等于对任何能连上端口的人敞开，宁可不启用，也不接受来源不明的拍板。

除 QQ 外还有两条通道：`localLoopbackChannel` 用于本机自测，`agentWire` 用于跨端投递。

## 密钥与备份

**这个项目不自带任何密钥。** 所有 API Key 都由使用者自己申请、自己填写。

- 填写后存入本机加密存储，明文字段会在迁移时擦除。
- 换机时用「加密备份」导出 `.petbackup`，再在新机器上用同一口令导入；口令丢失无法恢复。
- 导入前会先留一份本地快照，选错文件或中途失败时还能退回去。
- 密钥可以在设置里手动轮换，换过之后旧数据仍然可读，不会因为换了密钥就打不开以前的记录。
- 密钥不会出现在日志、错误信息、诊断页或导出文件里；界面只显示掩码。

## 数据放在哪

全部在 Electron 的 `userData` 目录下，可用 `PET_DEVICE_ID` 区分不同设备：

| 文件 / 目录 | 内容 |
| --- | --- |
| `settings.json` | 全部设置 |
| `state.json` | 运行状态 |
| `secrets.bin` | 加密后的密钥 |
| `vault-keys.json` / `vault-state.json` | 加密仓库的密钥材料与状态 |
| `memory.bin` | 记忆（加密） |
| `chat.bin` | 聊天历史（加密） |
| `models/` | 导入的模型 |
| `sync/` | 本机目录同步 |
| `reports/` | 每日巡视报告 |
| `notes/reflection/` | 反思笔记 |
| `balance-ledger.json` | 余额记账 |
| `rps-state.json` | 猜拳战绩 |
| `tasks.log` | 任务日志 |

同步只写本机目录，默认 `userData/sync`，可用 `PET_SYNC_DIR` 改到别处（比如网盘挂载点）。不连任何远端端点。

## 环境变量

| 变量 | 作用 |
| --- | --- |
| `PET_MEDIA_ROOT` | 临时改模型目录（开发期用） |
| `PET_SYNC_DIR` | 改同步目录 |
| `PET_DEVICE_ID` | 设备标识，默认 `desktop-local` |
| `PET_SELFTEST` | 设为 1 时启动后跑自检 |
| `PET_LIVE2D_PROBE` | 指定探针目标，走 URL query |
| `PET_VAULT_SMOKE` | 加密仓库冒烟 |
| `PET_VAULT_INIT_SMOKE` | 加密仓库初始化冒烟 |

## 目录

```
apps/desktop/           桌面壳：窗口、托盘、IPC、聊天窗、设置窗
apps/desktop/electron/  主进程、模型库、备份、巡视、状态栏指标
apps/desktop/electron/renderer/  渲染、动作、描边、气泡、状态栏
packages/shared/        类型、配置 schema、事件总线、错误码
packages/core/          渲染契约、模块系统、远程通道、记忆、陪伴、网络
packages/vault/         加密存储
packages/memory/        记忆层
packages/ui/            设置界面
scripts/                门禁、冒烟、契约快照、素材体积审计
assets/                 表情与立绘（自制，授权见 check-assets-license）
```

## 已知限制

- 桌面壳的功能仍是内建实现，还没有加载第三方模块。
- 聊天只支持 DeepSeek，不支持自定义端点。
- Live2D 需要自己准备模型文件，仓库里不带。
- 动作表目前只有点头和摇头两个动作，扩展要自己加轨道。
- 本机同步只做到「写进一个目录」，没有跨设备冲突合并。
- 状态栏的电量与 GPU 利用率在部分机器上拿不到，界面显示「—」属正常。
- 余额监控的轮询尚未接进桌面壳；阈值告警与确认也未接入。
- 还在开发，暂不发布。
