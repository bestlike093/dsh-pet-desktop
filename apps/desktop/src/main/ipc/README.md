# ipc 模块硬规

1. `ipc/**` 只能通过依赖注入接收主进程单例，禁止以任何形式 import `electron/main.mjs`（含相对路径、`require`、动态 `import()`）。反向依赖会让装配层与通道层重新缠死。
2. 搬迁只允许移动注册位置：channel 名、`invoke`/`send` 形态、参数顺序、返回结构都不能顺手改。
3. 每个 channel 全仓只注册一次；注册面必须等于 `IPC_CHANNELS` 白名单。
4. 查询模块不写盘、不改设置、不主动 `send`。模块内缓存属于实现细节，对外仍按只读语义归类。
5. **查询语义优先**：一条通道归 `queries` 还是 `mutations`，看对外承诺的语义，不看实现里有没有写内存。
   - `voice:status`：对外只回答「语音服务现在能不能用」，10 秒探测缓存只是加速，归 `queries`。
   - `balance:query`：对外包含刷新余额与记账，会写台账和 `lastKnownBalance`，归 `mutations`。
   - `presence:mood`：只读当前心情，不推进状态机，归 `queries`。
   - 缓存只有在模块内单一写者时才算实现细节。一旦出现第二个写者，就升级为共享状态，重新裁定归属。
6. 内部通道白名单只增不改。白名单条目必须写明「为什么只内部触发」；要让渲染侧可调，必须同时改 `preload` 和契约快照，不能只从白名单里删。
7. `dialog`、`winManager`、设置窗口这类外壳能力，等六域全部搬完后统一收成 `ShellDeps`，不要每个域各注入一遍。
8. 每搬迁一域，必须补该域的 channel invoke 冒烟；覆盖范围按域增长，不攒到最后一次验。备份这类有副作用且怕连点的通道，还要验并发与中间态。
9. 有副作用的互斥通道（备份，以及后续聊天、记忆写）锁跟随主进程任务，不跟随发起窗口：渲染进程断开、窗口隐藏或销毁都不中断已经开始的写盘。释放只走 `finally` 一条路径——成功、失败、中断都从同一处落回，不在 `try` 或提前 `return` 里单独解锁。第二次并发 invoke 直接返回 `BusyResult`，不排队、不产第二份结果。锁状态用内部 probe 通道观测，测试不靠 sleep 赌时序；**probe 禁止当轮询原语**，等完成走 invoke 的 promise 或上层 done 信号，不要自旋读 `inFlight`。probe 只在非 production 注册，线上没有误用入口。这条规则按域复用，不各写一套。
